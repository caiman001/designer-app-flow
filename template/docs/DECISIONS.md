## 一、产品 P

**P1 · 少一步是一步：设计和验收先看第一性原则和美观** — 沿用 · 依据：一、二、四
- 设计和验收的优先顺序：①第一性原则（这一步 / 这个控件为什么存在、能不能不要）②美观（对画布、对设计系统、细节到位）③功能齐全。拿不准时宁可少做。
- **操作成本是验收项**：核心任务每次都数步数（点按 + 输入 + 换屏 + 需要看清才能点的停顿），记在 [qa/task-steps.md](qa/task-steps.md)。新设计不比上一版多一步；多了要写理由给用户定。能默认替用户决定的不问，能一次做完的不分两步，能在原地做的不跳页。
- 验收报告写每个改到的任务「几步 → 几步」；试用员按真实用户的路径走，不按代码的路径走。

## 二、交互与动效 M

**M1 · 动效单独一个阶段** — 沿用 · 依据：四
- 关键因果动画单独成阶段做；参数只在 `Motion.swift`；每个时刻录屏 0.25 倍速检查，触感真机试；减弱动态效果时降级为淡入淡出。

**M2 · 先画布，后代码** — 沿用 · 依据：七
- 布局 / 组件 / 新交互先改 Design 画布给用户看，认可后才写 Swift；宣发物料同样先画布分镜。截图永远不能当设计稿。小改（文案、间距、删一个元素）可以画布和代码一起改。
- 画布保持干净正确：只留现行界面和定稿；探索方向定了就删掉没选的，设计改了就替换原画板（不留「v2」「示意」并排）。
